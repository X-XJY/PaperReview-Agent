# 架构与数据边界

原创业务实现，未复制参考项目业务代码。领域本体位于 `backend/ontology.json`，Prompt 位于 `backend/prompts.py`，契约位于 `backend/schemas.py`。

## 执行流程

PDF → MinerU 精准 API → 内容块 / Markdown 回退 → Agent1 元信息 → Agent2 分块方法拆解 → Agent3 本体打标 → Agent5 原文核验 → Agent4 多篇聚合 → Agent5 聚合核验 → 前端渲染。

没有 LangGraph、CrewAI 或向量数据库。一个独立 worker 串行处理持久任务，避免多个任务同时重复请求同一缓存。每篇成功后立即保存，单篇失败不清空其他成功结果。worker 重启时恢复 running 任务，阶段调用与远程解析 ticket 可复用。必须只运行一个 worker 副本；横向扩展需要数据库租约和跨进程去重机制。

## 严格输出与证据

- 模型输出通过 Pydantic 严格验证，禁止多余字段。
- 支持 JSON Schema 的供应商可开启 `LLM_JSON_SCHEMA`；其他供应商使用 JSON mode 和服务端验证。
- evidence id 来自确定性解析块，不能由模型定义。大块继续拆分，保留页码和所有文本。
- 先验证引用存在，再调用核验角色，附相邻上下文。模型漏检/重复返回的项标记待核验。
- 方法和优势保留实验条件；作者局限不能通过常识推测。人工备注不进入已核验事实集合。
- 只把 supported 的论文 Claim 送入聚合事实集合。元信息、指标和分类核验问题在论文 warnings 中保留。
- 演进关系必须有合法端点、有效证据并通过核验；自环、虚构端点被删除。
- 共性问题至少涉及两篇论文，并经过聚合核验。
- 研究假设的 supported 表示前提依据有支持，不表示假设已被实验证明。

## 版本与缓存

解析：PDF SHA-256 + MinerU 模型及适配器版本。阶段缓存：输入内容 + Prompt 完整文本/版本 + JSON Schema + 模型标识/URL/参数。任务复用同时检查流水线配置签名。

人工修正创建 append-only revision；原文不可编辑。字段标记 unverified，job.stale=1，保留旧聚合结果并明确标为过期。重新推导会核验已改论文、重做其分类、聚合和聚合核验，不重新解析 PDF。通过 revision 比较阻止旧页面覆盖新修改。

缓存只在后端内部按内容寻址；浏览器必须拥有任务会话才能访问论文、报告和 PDF，不提供以哈希直接读取他人数据的接口。

## 持久目录

`data/app.db` 保存会话、任务、中间产物、缓存、修订。`data/files/<session>/<hash>.pdf` 保存上传原文。Docker 使用持久 volume，重启不丢任务。默认会话与缓存保留 7 天，worker 每小时清理已过期且无运行任务的会话数据。

## 第一版局限

元信息核验目前以元信息对象为单位记录告警；不是逐作者/逐会议字段的独立校验。只支持单篇一个核心方法图节点。人工表单优先覆盖方法、优势、局限与未来工作。相同模型的自检可能出现相关性错误，不能替代人工评测。上下文过长会明确失败，不静默截断。预印本和正式出版版本目前不做 DOI 合并。

Sites 静态预览仅运行 React 教学样例（编辑保留到页面关闭）；FastAPI + worker 必须独立部署。绝不在静态示例中伪装模型调用成功。

可选 WebMCP 只暴露读取当前分析状态的工具，浏览器不支持时无副作用跳过。本开发环境浏览器连接不可用，未做实际 WebMCP 注册/调用验证，也未执行浏览器交互自动化；构建和后端接口测试独立完成。
