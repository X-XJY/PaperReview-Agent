# 研脉 AI 论文助教：开源调研与实施建议（待确认）

调研日期：2026-09-11。本轮只形成方案，没有修改业务代码、安装依赖或更改线上服务。

建议定位：帮助计算机专业学生和研究者读懂当前批次论文的证据型助教。沿用每批最多 8 篇、现有解析缓存和人工修正机制，提供论文问答、分层讲解、跨论文比较及理解检查。

## 2. 推荐产品范围

首版提供四种入口，默认直接讲解，用户主动切换启发模式：

1. **问论文**：基于所选论文回答方法、实验设置、指标和作者局限。可从任意论文卡片或证据块点击“问助教”，自动携带上下文。
2. **讲明白**：支持直观解释、技术细节两档；按“概念—工作过程—例子—适用条件”展开。公式按“原式—符号—步骤—直觉”解释。
3. **比较论文**：以用户指定维度比较当前批次，分别为各论文陈述绑定证据；样本、任务、划分、指标不一致时提示不可直接比较。
4. **检查理解**：针对当前概念提出一道简答题；按用户答案给出反馈，依次提供提示、关键步骤或完整讲解。用户随时可选择直接查看答案。

教学记录只保存可观察事实：学过什么、哪题答错、用户自选深度、下一步复习点。不推断“疲劳”“智力”，不用少量答题记录给出精确掌握率。

首版暂缓语音、课程排课、教师后台、长期跨设备画像、间隔复习调度、自动联网搜论文和代码执行。这些可在核心问答验收后扩展。

## 3. 相对参考项目的具体改进

**区分三类回答内容。** 论文事实必须有原文证据；背景知识与教学类比明确标注“背景讲解”，不伪装成作者结论；研究假设标注“待验证”，绑定支持其前提的论文证据。用户可开启“仅依据论文”模式，关闭无文献来源的背景补充。

**引用由服务器落地。** 模型只选择允许的 evidence id，服务器回填论文名、页码与真实片段。引用存在不等于支持结论，还需检查语义、作者归属与实验条件。无有效来源的论文事实不得显示为已支持。

**纠错与助教联动。** 人工修正后，相关索引和答案缓存按修订版本失效；旧消息保留但标记来源已更新。人工备注不自动升级为论文事实，重新核验的修正结果才可作为已核验摘要参与回答。

**既回答，也检查是否理解。** 不强迫每次反问。直接模式先回答；引导模式每轮只追问一个关键点，最多两级提示后允许展开完整解释。

**承认检索边界。** 找不到证据时表述为“当前所选材料中未检索到”，不能推断“论文绝对没有”或“领域没人研究”。引用不足时给出缺少哪类材料及可调整的检索范围。

## 4. 架构与技术选择

保留 React + FastAPI + SQLite + MinerU API + DeepSeek。4+1 分析流水线仍负责批量分析；助教是按需调用的独立模块，不在每次提问时重跑整篇分析。

流程：

```mermaid
flowchart LR
  A[问题、选定论文、阅读位置] --> B[会话权限与修订检查]
  B --> C[问题路由与中英检索词]
  C --> D[原文证据和方法卡片检索]
  D --> E[结构化教学回答]
  E --> F[引用与语义校验]
  F --> G[答案、证据侧栏、理解检查]
```

这些是处理步骤，不代表六次模型调用。权限、范围、检索、引用回填均由代码执行；一般每轮一次生成、一次核验。中文问英文论文或指代不清时增加一次查询改写。结构修复及重检索共用硬预算，每轮所有调用合计最多 5 次；达到上限明确结束，不递归无限重试。

### 检索

- 复用 MinerU 已有 evidence 块，保留原文及稳定 id；检索子块保存父 evidence id 和文本偏移，不改变原始证据。
- 两路候选：英文原文关键词检索，以及中文方法卡片/术语说明检索后回溯原文。显式选中的证据优先；跨论文比较按每篇分别召回，避免只检索到一篇。
- 首版采用 [rank-bm25](https://github.com/dorianbrown/rank_bm25) 和自定义中英预处理、缩写及术语映射；仅对当前批次按需索引，限制内存缓存总量。该工具不自动完成分词或跨语言语义检索，需要自行实现预处理。
- 候选初值每篇 4—6 块，按问题选出约 8—12 个相关块；这是待评测参数，遇到跨 8 篇的比较需保证每篇覆盖，超出预算时按比较维度分轮。
- 初版不运行本地大模型或额外向量数据库。中英同义改写仍可能漏检；若人工标注集召回未达标，再引入独立、可配置的远程 embedding 服务，不能默认现有聊天密钥具有 embedding 能力。

### 数据与并发

新增 tutor_threads、tutor_messages、tutor_tasks、tutor_usage，独立于批量 jobs 表。每个对象绑定服务器会话、任务、论文范围及 revision。不能信任浏览器传来的 evidence id 或 job id，读取前必须验证归属。

新增轻量 tutor worker，初始全局并发 1；使用独立队列，防止用户对话被长篇解析任务阻塞。FastAPI 只提交任务和返回状态，供应商请求不阻塞主接口；SQLite 事务中不等待网络。

现有 llm.call 与 jobs 用量绑定，开发时应抽出共同的请求、JSON 校验和修复逻辑，通过不同计量适配器服务两种任务，保留批量分析回归测试，避免聊天消耗被算入旧论文任务。

助教输出使用较小的 Pydantic 契约：回答段落、段落类型、引用 id、证据支持状态、必要的下一问。空值按字段定义，沿用此次已修复的字段级错误反馈；禁止为了过校验自动补造事实。

### 交互

桌面端使用可折叠助教面板，保留论文阅读区域；移动端使用独立面板。聊天顶部持续显示“当前论文/所选论文/本批全部”和直接/引导模式，切换论文不悄悄更换旧会话范围。

引用点击显示现有原文证据并跳到已知 PDF 页码。当前数据未保证坐标信息，首版不承诺精确框选高亮。公式通过 [KaTeX](https://github.com/KaTeX/KaTeX) 展示；解析缺失或损坏时要求核对原页，不凭记忆还原作者公式。富文本禁用原始 HTML 与不受信任的公式扩展。

首版采用任务状态轮询，先显示“检索中/生成中/核验中”，核验后呈现完整答案，避免先展示流式幻觉再撤回。后续可扩展状态事件流。

## 5. 缓存、版本和额度

缓存键至少包括：会话范围、任务、所选论文与修订版本、证据内容哈希、问题、有效对话上下文哈希、教学模式、模型及 Prompt/schema 版本。不能只按问题文本复用答案，更不能跨用户误用缓存。

历史答案只作为对话上下文，不作为新的原文证据；跟进问题重新检索。并发生成期间发生修订时，将结果标记过期并提示基于新版本重新提问。

不增加 MinerU 重解析调用。默认建议每会话每日 20 轮、全站每日 200 轮，同时设置全站 token 预算；最终额度按实际使用调整。每轮生成与核验分别设置输出上限，超限反馈明确原因。

费用按供应商实际输入、输出和缓存 token 分别记录，不在未测量前承诺“每问几分钱”。普通问答建议以 2—3 次调用为目标，所有重试硬上限 5 次。2GB 仅作为低并发 MVP 部署假设，需要用真实请求验证内存峰值和排队时间。

会话记录与现有系统一致默认保留 7 天。首版不宣称跨设备长期记忆；将来引入账号体系后再做长期学习档案。

## 6. 验收与演示

使用你提供的 Transformer 和 BERT 两篇，以及已有 RAG 论文建立至少 30 道人工标注题：论文事实、中英混合术语、公式解释、跨论文比较、证据缺失、错误前提与多轮指代均覆盖。人工标注答案所需证据，避免只让同一个模型给自己打分。

拟定验收门槛（目标，不是现有实测成绩）：

| 指标 | 目标 |
|---|---|
| 引用 id、论文归属、页码映射 | 所有展示引用通过服务器校验；不存在的引用拦截率 100% |
| 检索证据覆盖 | 标注题中，所需核心证据命中率至少 90%；跨论文题分别计算 |
| 论文事实支持率 | 人工抽检至少 90%，按原子陈述计；无依据事实不得标为已支持 |
| 无证据题 | 至少 90% 正确指出证据不足，不编出处 |
| 缓存与修订 | 重复请求命中；范围、模式、上下文、来源修订变化时正确失效 |
| 权限与提示注入 | 跨会话读取全部拦截；论文中的越权指令不改变检索范围 |
| 回归 | 现有 18 项后端测试及 Windows 打包检查继续通过 |
| 真机体验 | 两篇和八篇范围均实测；展示 P50/P95 响应时间、token 与内存峰值 |

延迟先以普通问答 30 秒内为设计目标，供应商波动和验证调用可能使其超时，不能当作已实现 SLA。额外评估用户能否在三轮内理解一个概念；小规模试用不宣称统计显著的学习提升。

比赛演示建议：打开 Transformer → 从具体方法卡片问助教 → 展开原文来源 → 切换引导模式做一道理解题 → 对比 BERT → 提出一个材料中无依据的问题展示边界 → 修改一条抽取结果并展示旧回答过期。

现有分类本体聚焦 RAG，而 Transformer/BERT 涉及更广的 NLP。助教检索不应被现有 RAG 标签强制过滤，也不应由助教自由生成新分类标签；本体扩展作为独立后续任务。

## 7. 排期与待确认范围

估计在现有项目上增量开发需要 5—7 个工作日，不代表对比赛剩余时间的判断：

| 阶段 | 交付 |
|---|---|
| 第 1 日 | 助教数据契约、会话与版本、标注题集、界面流程 |
| 第 2 日 | 原文/卡片检索、双语召回、权限过滤 |
| 第 3 日 | 生成、引用核验、结构修复、额度与缓存 |
| 第 4 日 | 助教面板、引用跳转、公式、跨论文比较 |
| 第 5 日 | 引导问答、单题理解检查、历史与修订失效 |
| 第 6—7 日 | 真实多篇评测、错误修复、Windows/Ubuntu 回归、部署与演示 |

三人可分别承担前端交互、后端证据与任务、测试标注与演示；Codex 在确认后负责代码实现。若剩余周期更短，第一交付只做有据问答、分层讲解、跨论文比较与证据跳转，将练习模式推迟。

推荐确认的范围：四种入口、直接/引导两种教学方式、段落级证据类型、轻量检索、按修订失效缓存、现有 DeepSeek/MinerU 复用、原创 MIT 实现。确认后再开发和部署。
